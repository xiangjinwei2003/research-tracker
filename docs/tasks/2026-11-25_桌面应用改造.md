## 3. 架构

同一份代码，两个运行环境。

| 项目 | 桌面应用（主力） | 网页版（保留） |
|---|---|---|
| 位置 | claude.ai 上的私有 Artifact，在 Claude 桌面应用里安装为应用 | Vercel，现有域名 |
| 数据 | 本机文件 `~/Documents/Research Tracker/research-tracker.json`，按天备份 | 浏览器 localStorage（不变） |
| 每日笔记 | 有 | 有 |
| 发送到 Claude Code | 有，子进程 `open` 打开 `claude://` 链接 | 有，浏览器打开 `claude://` 链接 |
| AI 整理提示词 | 有，sample quick 档 | 无 |
| 按申请计划分析 | 有，读取 melbourne-phd-waycott 的文件，sample default 档 | 无 |
| 全局快捷键、菜单栏计时、系统通知、置顶笔记窗口 | 有 | 无 |
| 苹果日历订阅 | 有，子进程 curl 上传到 Vercel 接口 | 有（不变） |

数据放本机文件，原因有三：

1. Claude Code 会话可以直接读这个文件；导师定时任务改提示词后也能读（见第 7 节），专注数据不再只在浏览器里。
2. 没有 Artifact 数据库单文档 256 KiB 的上限。
3. 文件在 `~/Documents` 下，Time Machine 和 iCloud 文稿同步都覆盖。

运行环境的判定：页面加载时同步检查 `window.claude.use` 是否存在。存在就是 Artifact，再等 `claude.use("desktop")` 返回，有 fs 模块才是安装后的窗口；在浏览器或 Artifact 面板里打开时只显示安装按钮。不存在就是网页版。设置里显示当前的数据位置。出错时报错，不在两种存储之间自动切换。

写入规则（防止空数据覆盖文件）：

1. 读到文件之前不写。zustand persist 水合前也会写，所以文件存储在打开成功前丢弃写入请求，界面在水合完成前不渲染。
2. 文件不存在时不自动建空文件，先让用户选「从网页版导入」或「从空白开始」。
3. 每次写入先写临时文件再 rename；同一时间只有一个写入，期间的改动合并成下一次写入。不设定时延迟，窗口隐藏时立即写。
4. 每天第一次写入前把旧文件复制到 `backups/`，保留 30 份。
5. 文件读不出或格式不对时停止写入并显示原因，与网页版的 unreadable 处理一致。

## 4. 数据模型（SCHEMA_VERSION 7 改为 8）

| 变更 | 内容 |
|---|---|
| NoteEntry | id、date（本地日期 YYYY-MM-DD）、text、level（缩进 0 至 3）、createdAt、updatedAt、projectId、todoId、sent（发送时间、工作目录、提示词、会话 id） |
| AppState.notes | NoteEntry 数组 |
| Todo.doneAt | 勾掉时记录时间，取消时清除，用于分析本周完成了什么 |
| Project.folder | 本机项目目录的绝对路径，发送到 Claude Code 时作工作目录 |
| AppState.analyses | 保存的分析结果，重复查看不再花额度 |
| 侧栏便签 | 迁移成今天的第一条笔记，侧栏的便签输入框移除 |

迁移函数放在 normalize.ts，遵守 README「给二次开发者的两个坑」。导入导出给 notes 与 analyses 加白名单归一化。

参照 Lody「每日笔记」规格（specs/today-outline.zh.md）的取舍：

| 做法 | 本项目 |
|---|---|
| 每天一页，今天在最上面，往下是更早的非空日期 | 采用 |
| Enter 新建、Shift+Enter 换行、Tab 与 Shift+Tab 缩进、行首退格合并到上一条 | 采用 |
| 笔记固定为一栏，与主区域并列 | 采用，固定在右侧；桌面版另有置顶的紧凑窗口 |
| 节点连同子节点转换为任务，转换后原行保留对话引用 | 采用，转换为提示词并发送；原行记下发送时间与会话 |
| 引用的对话显示实时状态 | P7 按桌面端会话记录显示标题与最后活动时间 |
| CRDT 同步、多成员、Lexical 编辑器、节点拖拽、三万节点性能目标 | 不做，单人单机使用 |
