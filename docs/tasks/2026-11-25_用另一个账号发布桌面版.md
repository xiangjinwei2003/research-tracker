# 用另一个账号发布桌面版

## 改动记录

1. 2026年11月25日。回答「我发到另一个号的Claude code桌面端之后出现了这个问题」（截图为桌面版的权限页：读写文件的权限不可用）。新建本文件。
2. 2026年11月27日。回答「开启后能用了」。「原因」一节开头新增一段：本机这次的实际原因为组织未开启应用完整访问，下面的跨组织说明对本机情况不成立。

## 原因

2026年11月27日核实：本机两个账号属于同一个组织，权限不可用的实际原因为组织设置未开启应用完整访问（平台提示 `ENOSYS: Your organization doesn't allow full access for apps.`），组织所有者在 claude.ai 管理设置里开启后可以使用。下面的跨组织说明是 11月25日根据文档写的推测，对本机情况不成立；只在两个账号确实属于不同组织时适用。

桌面版把数据存在本机文件，需要 desktop 能力的 `full-access` 权限。运行时 0.2.99 的 `desktop.d.ts` 规定：这项权限只授予同一组织里、没有外部人员写过的 Artifact；别的组织的账号通过分享打开时，这项权限被拒绝，状态一直是 `unavailable`，启动页停在权限页。原来那个 Artifact 由另一个组织的账号发布，所以在当前账号里用不了。

要在当前账号里用，就用当前账号发布一份自己的 Artifact。AI 整理与分析的调用随之计入当前账号的额度。

## 步骤（在当前账号的 Claude Code 会话里执行，工作目录为本仓库）

1. 运行 `npm install`（node_modules 已存在可跳过），再运行 `npm run build:artifact`，确认生成 `dist-artifact/research-tracker.html`。
2. 用 Artifact 工具发布这个文件，新建一个 Artifact（不传 `url`）：`capabilities` 为 `{"desktop": {}, "sample": {}}`，`icon` 为 `checklist`，`description` 为「科研项目的任务、日历、专注记录与每日笔记；安装为桌面应用后，数据保存在本机文件。」
3. 把返回的链接告诉用户。用户在当前账号的 Claude 桌面应用里打开链接，选 Install as app，第一次打开时允许读写文件。
4. 以后更新：在当前账号的会话里重新构建，用这个链接作为 `url` 发布到同一个 Artifact。每发布一个新版本，第一次用到读写文件时会重新询问权限。

## 注意

1. 仓库是公开的，不要把这个账号的 Artifact 链接写进仓库里的任何文件。
2. 两个账号的桌面版如果装在同一台 Mac 上，会读写同一个数据目录 `~/Documents/Research Tracker/`。数据文件按单一写入者设计，两个应用不要同时开着；不再用的那个可以在 Claude 桌面应用里卸载。
3. 数据迁移照常：在网页版「导出 JSON 备份」，新安装的桌面版首次运行时会列出下载文件夹里的导出文件。数据文件已经存在时（另一个应用建过），直接读取已有数据，不出现首次运行页。
